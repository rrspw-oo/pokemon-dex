# Architecture

[README](../README.md) | [繁體中文 README](../README.zh-TW.md)

Mobile-first Pokedex search tool with a Game Boy shell look and full-color pixel sprites. Deployed to GitHub Pages under `/pokemon-dex/` from `main`.

## Design

- Shell: warm gray body (`--shell`), dark bezel with power LED and title, warm light-gray screen (`--screen`) with a faint dot-matrix pattern and the asymmetric rounded bottom-right corner. No green palette.
- Chrome is neutral: dark ink (`--ink`), gray secondary text (`--ink-soft`), `--screen-deep` for the card count badge, gray hard shadows and tile borders (`--line`), pale yellow for the active suggestion and the current Pokemon in a chain (`--highlight`). Pokemon sprites and type badges stay in full color on white tiles (`--paper`, `--paper-hi`).
- Pixel UI: square 3px borders, hard 4px offset shadows, pressed state shifts by the shadow offset. Evolution and form mini cards have no border. The GO button uses the A/B-button magenta (`--button`).
- Fonts: Press Start 2P for Latin labels and numbers, Cubic 11 for Chinese and body text. Both are self-hosted subsets in `src/assets/fonts/`.
- Suggestion dropdown floats 8px below the search row with a 12px radius.
- Breakpoints: 2-column result grid by default, 3 columns from 600px, 4 columns and a two-column detail view from 860px, 5 columns from 1100px. From 860px the shell widens to at most 1280px (960px before) while the search box and the full-width 圖鑑 / 屬性 / 盃賽 tabs stay on two rows as on mobile; the footer text runs as one wrapping row.
- Evolution chain is horizontal: stages separated by a CSS line chevron (no solid arrow glyphs). Branching stages wrap into a grid of up to 3 columns, or 4 columns when the stage has 4 or more members (Eevee's 8 evolutions show as 2 rows of 4); below 600px those 4-column stages (`.evo-stage.is-wide`) use 52px sprites and 11px names without padding or wrapping so base + chevron + 4 columns fit at 375px. Mini sprites are 64px. Main-series evolution conditions are not shown. The full chain is always shown, including the base stage; the Pokemon whose page is open has the `--highlight` background and an underlined name, and its Pokemon GO evolution conditions show as chips below the chain. Tapping another Pokemon in the chain (or a Mega card) opens its page directly (history push, so 上一隻 and browser back return); there is no separate open button. The tap passes the evolution panel's current viewport top to `openDetail`, and `App.jsx` scrolls after the render so `.evo-panel` lands at the same position instead of jumping to the top.
- Card panel (卡牌): last panel in the detail view. From 860px (`matchMedia`, same breakpoint as the two-column detail) there is no toggle: the strip is always shown and the dashed divider above it is dropped, so nothing opens or closes on desktop. Below 860px the toggle (14px, 8px gap above it) reads 發卡 followed by the card count in a 24px round `.card-count` badge (`--screen-deep` background, half a step darker than the `--screen` toggle row, `--ink` text in the same font and size as the label; not black) while closed, and 收卡 while open. The strip (`.card-strip`, `min(40%, 160px)` columns, scroll snap, card ratio 63:88, 10px gap above it) is only rendered while open: closed, the panel shows just the toggle (no card backs or placeholders, the user asked for that); 發卡 shows the cards at once (no height animation, no loading step). Content below the toggle appears and disappears, so the toggle itself stays in place, except when the user scrolled to the very bottom of the page before 收卡: the page gets shorter and the browser clamps the scroll position. Under each open thumbnail: an "EN" tag for English cards, the set name (11px), and for cards with a stored price the price as `US$N` with the price month (`priceDate`, e.g. 2026.10) in 10px `--ink-soft` below it. Tapping a card opens a full-screen viewer (`.card-viewer`) with the large image (fixed width `min(100%, 420px, (100dvh - 140px) * 63 / 88)`, with a `vh` fallback, so the card, caption and buttons always fit the visible screen including phone landscape, and safe-area insets are respected; the fixed width also keeps the image from jumping; the already loaded low image appears first and is swapped for `high.webp` once it has downloaded, and the previous and next cards' large images are preloaded, because the TCGdex CDN often needs 2 to 6 s for a 100 to 180 KB large image), set name, number, price with month, and position (n / total). Buttons: 關閉 on the left and 下一張 on the right while a next card exists; on the last card 上一張 on the left and 關閉 on the right; a single card shows only 關閉. A horizontal swipe of at least 50px (and more horizontal than vertical, pointer events so touch and mouse both work) moves to the next (left swipe) or previous (right swipe) card; a swipe does not count as a backdrop tap. Backdrop tap and Esc close it. The thumbnail strip scrolls natively on touch; with a mouse it can be dragged (scroll snap is turned off while dragging via `.is-dragging`, and the click after a drag is swallowed so no card opens).
- All tokens and styles live in `src/index.css`.

## Behavior

- Language: Traditional Chinese and English (`src/i18n.js`). A TW / EN switch (Press Start 2P, 8px, the active one filled with `--bezel-text`) sits at the right of the bezel. The starting language is `?lang=zh|en`, then the saved choice (`localStorage` key `lang`), then `navigator.language` (zh* is Chinese, anything else English); switching updates `<html lang>` and, when the URL already has `?lang`, that parameter. UI strings are looked up by their Chinese text in the `EN` table (`useT()`, `{name}` placeholders); the `ZH` table only holds Chinese texts whose key differs from what is shown. Data carries both languages (see Data). In English mode no Chinese is shown anywhere: names show the English name only (no second line), types, moves, GO conditions, form names, cup names, rules and Remix differences come from the English fields, the card panel shows only English cards (no EN tag), and the home chips are Pikachu, #150, Alolan, Dark type, Catch Dark, Lure. Chinese mode is unchanged: Chinese name with the English name below.
- Typing shows up to 8 suggestions with thumbnails. Arrow keys, Enter, Esc supported (Esc only closes the list; the native search-field clear is prevented). On touch devices: suggestion hover highlighting reacts to `pointerType === "mouse"` only (iOS Safari swallows the click when a tap changes hover styling), and input blur closes the list after 200ms; picking or refocusing cancels that timer. Suggestion taps do not rely on `click`: a touch that moves less than 10px picks the item in `touchend` and calls `preventDefault()` so no ghost click reaches elements under the closing list; a longer drag only scrolls the list. Mouse still uses `click`. Placeholder: 輸入編號、名稱、屬性或進化條件 (12px below 600px so it fits a 375px screen, 16px above; the input text itself stays 16px). The home screen shows only the example chips, no hint line.
- Picking a suggestion opens that Pokemon's detail view; GO / Enter (and the home example chips) always show the result list, even for a single match.
- Navigation: tabs 圖鑑 / 屬性 / 盃賽 under the search box. All navigation goes through `go()` in `App.jsx`, which pushes `history.state = { view, pokemonKey?, from?, type?, type2?, cup? }`; popstate restores it. The detail view can open on top of any tab and its back label comes from `from` (上一隻 / 全部結果 / 屬性排行 / 盃賽).
- Detail view order: main card, evolution chain with Pokemon GO conditions, form changes, other forms, PvP panel (only when the record has `go_id`), card panel last (only when `cards.json` has the dex id). Detail type badges are buttons that open the 屬性 tab.
- Evolution panel: the picked Pokemon shows the conditions to evolve into its next stage(s) ("進化成X" + condition chips joined by a plain "+"); a final stage shows "由X進化成Y". The conditions are always those of the open Pokemon; when it has more than 2 next evolutions (Eevee) the panel shows 「點選進化後的寶可夢查看 Pokémon GO 進化條件」 instead, and tapping an evolution opens it with 由伊布進化成X. When the picked Pokemon can Mega Evolve (`go_evolutions.json` `megas`, read through `getMegas`), a 超級進化 block (原始回歸 for Kyogre/Groudon) follows with 96px mini cards for each Mega that open its page, and chips 首次 N 超級能量 / 之後 M 超級能量 (primal uses plain 能量 because the GO text file has no name for it). Species that do not evolve but can Mega Evolve (e.g. 勾魂眼) show this block instead of 「此寶可夢不會進化」. Megas shown there are left out of "其他型態".
- PvP panel: league tabs, 一般/暗影 toggle when PvPoke has the shadow entry, moves, rank, IV, then collapsible 擅長對付 / 剋星 (grid-rows 0fr→1fr transition, 48px pixel sprites in one row of 5). Collapsible toggles have no arrow: a `--screen` tinted bar that turns `--highlight` when open, 6px apart, no dashed dividers.
- 屬性 tab (`TypeView.jsx`): type chips, second-type chips (only existing combinations, with counts), league tabs, top 5 by PvPoke rank (shadow entries as separate rows), "看全部排名" toggle, league tags for ranks within 100, then the full type grid. Type ranking rows carry the same collapsible 推薦招式 / 擅長對付 / 剋星 blocks as cup rows (moves from `pvp.json` for the selected league).
- 盃賽 tab (`CupView.jsx`): a league picker (小小盃 CP 500 / 超級聯盟 CP 1500 / 高級聯盟 CP 2500 / 大師聯盟) with own pixel ball icons (`LeagueIcon.jsx`, drawn in SVG, not game assets), then the cups of that CP; the picked league is kept in `history.state.league`. Cup cards show no rules (the detail has them); a Remix card shows only its difference from the base cup (多禁 N 種 and 多開放 M 種, each kept on one line), and the detail lists those names under the rule chips. Each cup card shows the cup's official icon and, in the list only, the name without the league qualifier (：超級聯盟版 / ：高級聯盟版 / ：迷你版 / HLVer. / leading UL or ML, and X小小盃 becomes X盃); Remix or Rmix is drawn as an 8px "Remix" superscript anchored to the last character (absolute, so it never pushes the name to a new line); text after a remaining "：" becomes an 11px subtitle under the name (e.g. 假日盃 / 超越時間的旅程). The cup detail keeps the full name with a 48px icon. Cup detail shows rules, top 30 (Chinese name with the English name in 11px gray under it, types on the right, no score) and collapsible matchups/counters; a 擅長對付 or 剋星 block with no opponents is not rendered (no 無資料 placeholder). Recommended moves are in a 推薦招式 collapsible placed before 擅長對付 / 剋星 at every width (no inline move chips under the name). Cups without a PvPoke cup ranking are filtered from the league ranking; no "estimate" label is shown. Their matchups and counters come from the whole league ranking in both directions (A beats B when B lists A as a counter or A lists B as a matchup, and vice versa), filtered to eligible Pokemon, first 5 kept; mono-type and old regional cups (格鬥盃, 超能力盃, 電氣盃, 神奧盃, 洗翠盃 and similar) still have few or none because the open-league data rarely pairs those Pokemon.
- Shadow Pokemon use `ShadowIcon.jsx` (own pixel purple flame SVG, not a game asset) and a purple glow on the sprite. Form names never contain "的樣子" anywhere (e.g. 雷丘(阿羅拉), 肯泰羅(帕底亞・水瀾種), 蕾冠王(騎白馬)): `build-forms.mjs` strips it from `form_zh`, and `build-go-evolutions.mjs` strips it from GO option labels, 限X lines and form-change names, so the UI shows data as is.
- PvP panel (`PvpPanel.jsx`): league segmented control (超級聯盟 1500 / 高級聯盟 2500 / 大師聯盟 10000), rows 一般招式 / 特殊招式 (type-colored chips, 菁英 marks Elite TM moves), 聯盟排名, 推薦 IV. `pvp.json` is loaded with a dynamic import so it is a separate chunk. IVs come from `src/utils/pvpIv.js`: all 4096 IV combinations, highest level up to 50 that stays under the cap, ranked by stat product, ties broken by higher CP then higher attack. Base stats are kept in the data but not displayed. Tapping a mini card in the chain, the Mega block or "其他型態" opens that Pokemon.
- Browser back returns from the detail view (`history.pushState` with `pokemonKey` and `from`: "pokemon" or "list"); reloading keeps the open Pokemon. The detail card header has the back button on the left (label 上一隻 when `from` is "pokemon", 全部結果 otherwise, CSS chevron) and dex number plus types on the right.
- Detail markup: `.detail-col-a` (main card, evolution, 型態變化, 其他型態) and `.detail-col-b` (PvP, cards). The DOM order is the mobile order, so below 860px the columns simply stack.
- Desktop detail layout from 860px: a `minmax(300px, 380px) minmax(0, 1fr)` grid with both columns aligned to the top (no stretching), so the left column holds the main card and everything about evolution and forms, and the wider right column holds PvP and the always-open card strip; the page scrolls normally. In the left column, 4-column evolution stages use the 52px sprites and unwrapped 11px names. A fixed one-screen three-column layout was tried and dropped: at laptop heights (for example 1000x727) the main card, evolution and PvP do not fit and the panels end up squeezed or clipped.
- The PvP panel shows no source or methodology note on any screen size; attribution lives in README only.
- Form-change panel (型態變化) for species in `go_forms.json`: mini cards for every form, tap to see GO conditions (forms with no transition show 「目前無法透過型態變化獲得，在官方有活動時方可進化」), link to the form's page when it exists in the database. "其他型態" then lists only forms not linked there. Mini card names wrap inside the card.
- Card panel (`CardsPanel.jsx`): `cards.json` is loaded with a dynamic import when the detail view opens; card images are only rendered while the panel is open and use `loading="lazy"`, so no image is fetched until 發卡 is tapped. Images are loaded through the wsrv.nl image proxy (`https://wsrv.nl/?url=assets.tcgdex.net/<img>/low|high.webp`, Cloudflare edge with a Hong Kong node): measured from Taiwan, the TCGdex asset host (a single nginx server, no CDN) took a median 2.5 s per 20 KB thumbnail (max 8 s) and 3.6 to 5.7 s per large image, while the proxy took 0.6 s cold and 0.3 s warm for thumbnails and about 1 s for large images; the proxy re-encodes at the same size (600x825 / 245x337, about 3% smaller). The thumbnail chain is proxy webp (with `crossOrigin="anonymous"`, the proxy sends a single CORS header), then the direct TCGdex webp, then the direct jpg; a card whose image still fails is dropped from the strip (and from the viewer list), and when every card fails the panel shows 「此寶可夢暫搜尋不到卡牌」 instead of the strip. The viewer keeps the "?" placeholder for a single failed image. When 發卡 is tapped, every thumbnail's proxy low.webp is also requested with an anonymous-CORS `new Image()` (same request mode as the `<img>`, so nothing downloads twice) so off-screen cards are ready when the strip is scrolled. Thumbnails show a `--screen` card-shaped background until they load. Direct TCGdex images are loaded without `crossOrigin` because that host intermittently sends `Access-Control-Allow-Origin: *, *`, which browsers reject; the service worker caches them as opaque responses in `cards-cache` (statuses 0 and 200, 60 entries, 30 days), and proxy responses in `cards-proxy-cache` (status 200 only, 300 entries, 30 days). Prices are not fetched at runtime: they are the build-time snapshot in `cards.json`. Cards with a stored price move to the front, most expensive first; the rest keep the data order (zh-tw, then English). The viewer uses the same order. All species share the cards of their dex number, so form pages (Mega, regional) show the species' cards.
- The browser tab title (`index.html`) is "POKÉMON OMNISEARCH: Pokédex, Pokémon GO evolutions, PvP and cards in one search". The bezel title reads "Pokémon OmniSearch", shown uppercase as POKÉMON OMNISEARCH. Press Start 2P's own É is a shortened E, so the title renders a plain E inside `.title-acute` and draws the acute as two em-sized pixels with `::before`, keeping it the same height as the other letters. Clicking the title resets everything.
- Installed PWA (`display-mode: standalone`): `html` and `body` use `overscroll-behavior-y: none`, so the page does not rubber-band when there is nothing to scroll (the home screen fits the screen exactly); normal browser tabs keep their default overscroll and pull-to-refresh.
- PWA updates (`src/utils/pwaHelper.js`, `vite.config.js`): the generated service worker uses `skipWaiting` + `clientsClaim` and serves navigations from the precached `index.html` (`navigateFallback`), so GitHub Pages' 10-minute HTTP cache on `index.html` cannot serve a stale page. The page checks for a new `sw.js` on load, whenever it becomes visible (home-screen app resumed), on `pageshow` from bfcache, and every 30 minutes; it reloads on `controllerchange` except for the very first takeover after a fresh install. Precache includes js, css, html and the woff2 fonts; sprites use the runtime `sprites-cache`.
- PWA manifest lives only in `vite.config.js` (generated `manifest.webmanifest`, linked by the plugin): name and short name POKÉMON OMNISEARCH, theme and background `#c9c6be`, standalone, portrait. `index.html` keeps `theme-color` `#c9c6be` and `apple-mobile-web-app-title` POKÉMON OMNISEARCH for iOS. The old `public/manifest.json` (blue `#3b82f6` theme, linked from `index.html` ahead of the plugin's file) was removed.
- Footer is a flex row: text block on the left, rotated speaker grille on the right, vertically centered with the text.
- Footer: "© 2025 yRwRy · MIT License" plus a small (10px, system CJK font) line with the Pokémon copyright holders and data credits (PokeAPI, PvPoke, PokeMiners, TCGdex), "yRwRy" in the copyright line is a mailto link to wpsrrr@gmail.com (title "collab"). The project code is MIT (`LICENSE`, copyright holder yRwRy); `src/customContent/` images are excluded.
- Custom Pokemon (`src/data/customPokemon.js`) only match exact queries and never appear in suggestions.

## Search

`src/utils/searchIndex.js` scans all 1217 records per query (under 5ms). Chinese queries also match GO evolution condition text (`go_evolutions.json` lines, substring or all characters present) and return the pre-evolution with a `hint` string, merged per Pokemon: "condition進化" (e.g. 磁鐵模組進化) when it has one matching evolution, "X：condition；Y：condition" when several. A query containing 誘餌 is treated as 模組; score 45, below name matches. English queries of 3 or more letters also match the English condition lines (every typed word must start a word of the line, e.g. "catch dark", "magnetic lure", "walk") and set `hintEn`: "X to evolve" for one matching evolution, "Target: X; Target: Y" for several. A query that is a type name (zh or en, optional 屬性/系/type suffix) adds all Pokemon of that type at score 40. Scoring: exact > prefix > word prefix > substring; Chinese also matches when every typed character appears in the name. Chinese names and queries are NFKC-folded and lowercased first, so 超級噴火龍X or 超級雷丘y match the full-width Ｘ/Ｙ in the data. When an English query has no hits, it falls back to edit distance against species names (1 typo up to 4 letters, 2 up to 8, 3 beyond). Numbers match the exact id first, then id prefixes. There is no debounce because search is synchronous.

## Data

- `src/data/complete_pokemon_database.json`: one record per species or form. `sprite` is set only when the PokeAPI sprite path differs from the id (forms such as `10155`, `412-sandy`); shiny is always `shiny/<sprite>`. `gmax_sprite`, `form_zh`, `form_en` exist only where relevant. Display names are `form_zh || name_zh_tw` and `form_en || name_en`.
- `src/data/evolution_chains.json`: species to chain mapping plus flattened chain nodes; null fields are omitted. Only the chain structure is used by the UI.
- `src/data/go_evolutions.json`: `byTarget[dex]` is a list of options `{ from, lines, en, form?, formEn? }` for evolving into that species in Pokemon GO; `en` is the English line for each entry of `lines` (same order), built from the official GO English text file and English templates in the script (e.g. "25 Candy", "Catch 32 Dark-type with it as buddy", "Walk 10 km as buddy", "Magnetic Lure", "Rainy Lure or rain", "Galarian form only", "Daytime only", "No Candy cost if traded"); options are compared and deduped on the Chinese text. `lines` are ready-to-show Traditional Chinese strings built from the game master and the official GO zh-TW text file (item, lure and type names). Quest lines are composed by the script in a short form from the quest structure, e.g. 設為夥伴捕捉 32 隻惡屬性, 設為夥伴戰勝 30 隻幽靈/超能力屬性, 和夥伴步行 10 公里, 和夥伴獲得 70 顆心心. Lure lines are shortened to the module name (磁鐵模組, 藥草模組, 冰寒模組, 雨露模組); `LURE_WEATHER` in the script adds the in-game rain alternative for the Rainy Lure Module (雨露模組或雨天), which the game master itself does not encode. Standard templates win over form templates; form-only evolutions get a "限X" line (e.g. 限伽勒爾); regional-form branches whose conditions differ from the standard one are kept as extra options labeled with the region (e.g. 伽勒爾; the standard one is then labeled 一般), e.g. Galarian Slowpoke and Galarian Zigzagoon; condition search returns the regional source record for those; Community Day and buddy-event quest variants are ignored; options that differ only by gender are merged. `megas[dex]` lists `{ goId, cost, next }` for each Mega or Primal form of that species from the `temporaryEvolution` branches (first and subsequent energy cost); all 61 link to database records.
- `src/data/pvp.json`: `cpm` ([level, multiplier] for 1 to 50 in 0.5 steps), `moves[id] = [zhName, type, isFast, enName]` for every PvPoke move (English name from PvPoke), `ids` (PvPoke species ids referenced by matchups), `pokemon[goId or goId_shadow] = { s: [atk, def, hp], 1500|2500|10000: [rank, score, moveset, eliteMovesInMoveset, matchupIdIndexes, counterIdIndexes] }`.
- `src/data/cups.json`: `{ ids, moves, cups: [{ id, zh, en, cp, standard, icon, rules, rulesEn, diff?, source: "pvpoke"|"derived", top: [[idIndex, score, moveset, matchupIdIndexes, counterIdIndexes]], megaTop? }] }` built by `scripts/build-cups.mjs` from the game master `combatLeague` templates (VS_SEEKER only, deduped by zh title). The three Mega Edition leagues (`*_MEGAS`, `allowTempEvos`) use PvPoke's `mega` rankings; the GO text file only names the master one (大師聯盟：超級版), so the script names the others 超級聯盟：超級版 and 高級聯盟：超級版. They carry `megaTop`: the first 30 Mega/Primal entries of that ranking as `[idIndex, score, moveset, matchups, counters, overallRank, [iv, level, megaCp, baseCp]?]`, where the last part (capped leagues only) is the best stat-product IV for the Mega's own stats under the cap (`pvpIv.js`), its level and CP, and the CP of the same IV and level before Mega Evolving. The cup detail shows a 全部 / 只看超級進化 toggle for these cups; mega rows keep the overall rank number and show 進化前 CP / 超級進化 CP / IV as three wrapping phrases (the level is kept in the data but not shown). Rules add 可超級進化 (plus "CP 超過上限時對戰中自動調降" for capped leagues, per the official announcement; how GO lowers the CP is not published), and banned lists of one or two Pokemon are named (禁用 百變怪、脫殼忍者). `en` is the league title from the GO English text file (the two unnamed Mega Edition leagues are Great League: Mega Edition and Ultra League: Mega Edition), and `rulesEn` the English rules in the same order as `rules`. In English mode the cup list strips ": Great League Edition", ": Ultra League Edition", ": Little Edition", a leading UL/ML before Premier Classic and "Little" before "X Cup"; text after ": " becomes the subtitle. `diff` exists only on Remix cups (zh ends in Remix or Rmix): `{ base, baseEn, removed, added, removedEn, addedEn }`, where `base` is the cup zh name without the Remix suffix and the lists are zh names of Pokemon allowed in one cup but not the other, compared over the same PvPoke pool with the same eligibility check. `icon` is a file stem in `public/cup-icons/`: the script downloads each league's `iconUrl` from the game master once, trims it, and stores a 24x24 palette PNG (sharp), shown at 32px in cards and 48px in the detail title with `image-rendering: pixelated`; the app never loads the original Niantic URLs. Eligibility mirrors the GO rules (CP, types, whitelist, banlist, bannedPokemon); type-wide bans are summarized as "禁用 X 屬性" when at least 95% of a type is banned, with named exceptions. PvP data and cup data are loaded lazily through `src/services/pvpData.js`. Records link to it through `go_id` (PvPoke speciesId) written by `scripts/build-pvp.mjs`; shadow variants are not linked. Battle-only or not-in-GO forms (Ultra Necrozma, Eternamax, Zen mode, Bloodmoon Ursaluna, etc.) have no `go_id`.
- `src/data/go_forms.json`: `{ [dex]: { forms: [{ id, zh, en, sprite }], to: { [formId]: [{ from?, fromEn?, lines, en }] } } }` from the game master `formChange` entries (Furfrou, Hoopa, Kyurem, Necrozma, Shaymin, Zacian, Zamazenta, Zygarde). Forms link to database records by sprite stem.
- `src/data/cards.json`: `{ sets: { [setPath]: name }, cards: { [dex]: [img] }, prices: { [img]: usd }, priceDate }`, at most 6 zh-tw plus 6 English cards per dex (159 KB, 35 KB gzip; 1025 dex numbers, all with English cards, 724 also with zh-tw cards, 7711 cards, 394 stored prices, `priceDate` 2026.10). `img` is the asset path without host or size, e.g. `zh-tw/S/S8a/014`; `setPath` is `img` without its last segment and the card number is the last segment, both derived in `toCard` in `CardsPanel.jsx`. `prices` holds the TCGplayer market price (lowest `marketPrice` among the card's variants, rounded to whole US dollars) only for kept English cards worth at least `PRICE_MIN` (100); `priceDate` is the latest TCGplayer `updated` month among the fetched cards, formatted YYYY.MM. Prices are a one-time snapshot and only change when `data:cards` runs again with `--refresh`. Built by `scripts/build-cards.mjs` from the TCGdex API for every dex number in the database; dex numbers with no card are left out. Card names, images, set names, release dates and set sizes come from each set's detail (`/sets/<id>`); TCG Pocket sets (serie `tcgp`) and cards without an image are skipped. zh-tw cards: TCGdex zh-tw cards have no dex number, so they are matched by name against `name_zh_tw` (parenthesized part removed) after stripping regional / 光輝 / 起源 / 超級 prefixes, V / VMAX / VSTAR / V-UNION / ex / EX / GX / BREAK suffixes and a Mega X/Y letter, also trying the first word and the part after 的 (e.g. 火箭隊的超夢), dropping a `<阿響的>` style owner prefix, and mapping card-only translations through `ZH_ALIASES` (電飛鼠, 胡帕, 連擊/一擊武道熊師); unmatched names go to `node_modules/.cache/tcgdex/cards-report.json`. zh-tw cards have no rarity in TCGdex, so special cards are recognized by a number above the set's official card count (secret rares such as SAR, UR); those come first, then newest first. English cards come from `/en/cards?dexId=eq:<dex>` (the plain `dexId=<dex>` filter is a substring match, e.g. 4 also returns 14, 40, 104); every candidate's detail (`/en/cards/<id>`, 16440 cards) is fetched for its rarity and price. The English 6 are the `MAX_BY_PRICE` (3) most expensive cards at or above US$100, then the most special by `RARITY_TIER` (rarity text to tier, e.g. Special illustration rare 6, Illustration rare 5, Double rare 3, Rare Holo 2), then secret number, then price, then newest. Rarities missing from `RARITY_TIER` are listed in the report. An `en/` prefix marks an English card. API responses are cached in `node_modules/.cache/tcgdex`; `-- --refresh` downloads again (the full run takes about 30 minutes). Requests run 4 at a time with retries, because TCGdex answers 503 under heavier load. TCGdex GraphQL has no prices and failed for bulk queries, so it is not used.
- Partner Pikachu and Partner Eevee were removed from the database because they do not exist in Pokemon GO.
- `build-forms.mjs` adds a record for every Mega/Primal form in the game master that the database lacks (name from `pokemon/<name>-mega[-x|-y]` on PokeAPI, stats and types from PokeAPI, `is_variant: true`), then matches it like any other form. PokeAPI and the GO text file have no Chinese name for the newest ones, so `megaZh` composes 超級X / 超級XＸ / 超級XＹ / 原始X from the species name (e.g. 超級雷丘Ｘ, 超級烏賊王). This added 11 records (1217 total). Every record with `form_zh` also has `form_en`; `FORM_EN_OVERRIDE` in the script names forms PokeAPI leaves blank (Pyroar (Female), Meowstic (Female), Aegislash (Blade Forme), Zygarde (10% Forme), Zygarde (Complete Forme), Wishiwashi (School Form), Minior (Red Core)), and the base records of those species use the plain species name in `name_en`.
- These files are generated or corrected by scripts; see the data section of [README](../README.md) (資料更新 in [README.zh-TW](../README.zh-TW.md)). Run `data:forms` before `data:pvp`, and `data:fonts` last.
